# UI 문구 설계와 검토

사용자가 화면에서 대상과 상태를 파악하고 다음 행동을 선택하도록 문구를 설계하라. 제목, 내비게이션, 컨트롤과 배치로 전달되는 의미를 확인한 뒤, 사용자의 판단이나 실수 예방에 필요한 설명을 더하라.

이 기준은 웹·모바일 앱의 제목, 빈 상태, 버튼, 토글, 설정 설명, 입력 도움말, 대화상자, 배너, 권한 안내와 온보딩에 적용한다. 랜딩 페이지와 슬라이드의 본문은 가치 전달·학습·설득 목적에 맞춰 구성하고, 그 안의 조작 요소에는 이 기준을 적용하라.

## 1. 실제 동작과 대상을 레이블에 명시하라

버튼을 누르면 무엇이 일어나는지 레이블만으로 예측할 수 있게 하라. `새로 만들기`, `관리`, `설정`, `확인`처럼 범위가 넓은 말은 실제 동작을 드러내는 표현으로 구체화하라. 저장을 실행하면 `변경사항 저장`, 다운로드를 실행하면 `보고서 다운로드`로 표시하라. 설정 페이지를 여는 버튼에는 `알림 설정 열기`처럼 이동 결과를 표현하라.

제목은 대상이나 작업의 이름을 담고, 버튼은 그 대상에 수행할 행동을 담는다. 같은 동작에는 화면마다 같은 용어를 사용하라.

## 2. 화면이 전달하는 의미를 한 번만 표현하라

제목·내비게이션·레이블·상태 표시와 보조 설명을 함께 읽어라. 보조 설명을 가려도 사용자가 같은 판단과 행동을 할 수 있으면 해당 설명을 제거하라. 영역 제목, 현재 상태, 실행 버튼이 역할을 충분히 전달하면 그 구성을 유지하라.

입력 형식이나 필수 조건처럼 컨트롤에서 알 수 없는 정보는 필요한 위치에 남겨라. 도움말을 배치하는 컴포넌트라도 실제로 보충할 정보가 있을 때만 그 영역을 렌더링하라.

## 3. 결정에 필요한 결과와 제약을 먼저 알리라

행동의 결과 중 사용자의 선택을 바꾸는 내용을 먼저 제시하라. 부수적인 처리 과정을 정리하고, 데이터 삭제·비용 발생·외부 발송·공개 범위 변경처럼 중요한 영향은 각각 보존하라. 여러 중요한 영향이 있으면 짧은 항목으로 구분하라.

저장 위치, 로그, 동기화 같은 내부 동작은 사용자가 무엇을 판단해야 하는지에 맞춰 표현하라. 예를 들어 저장 지연은 `저장 중`, 다른 기기에 반영되지 않은 변경은 `이 기기에만 저장됨`처럼 사용자가 알아야 할 상태로 전달하라. 감사 기록이나 데이터 보관 조건이 사용자의 결정에 영향을 주면 필요한 범위를 명시하라.

상태 변경의 영향을 생략하기 전에는 실제 제품 동작과 사용자의 배경지식을 확인하라. 사용자가 예상하기 어려운 기능 중단이나 데이터 손실은 해당 컨트롤 가까이에 설명하라.

## 4. 되돌리는 방법을 컨트롤에 맞춰 안내하라

같은 토글로 상태를 전환할 수 있으면 명확한 레이블과 현재 상태로 사용법을 전달하라. 별도 화면에서 복원하거나 제한 시간 안에 실행 취소해야 하면 경로와 조건을 안내하라. 복구할 수 없는 결과는 실행 전에 명시하라.

## 5. 빈 상태의 원인과 다음 행동을 구분하라

첫 사용 화면은 대상 제목과 구체적인 시작 행동을 기본으로 구성하라. 빈 목록과 버튼으로 상황을 충분히 이해할 수 있으면 설명과 일러스트는 선택 사항이다.

검색·필터 결과 없음, 로딩 실패, 권한 부족은 사용자가 취할 행동이 다르다. 상태를 구분하는 짧은 안내와 해당 행동을 함께 제공하라. 접근 가능한 이름과 상태 알림도 같은 의미를 전달해야 한다.

사용자가 시도할 법한 동작에 제한이 있으면 필요한 조건이나 권한을 해당 위치에 짧게 명시하라. 현재 제공하는 기능과 조작 요소에서 이미 드러나는 범위는 그 구조로 전달하라.

## 6. 사용 조건을 충족할 행동을 직접 제공하라

계정 연결, 권한 요청, 요금제 변경, 설정 활성화가 필요하면 해당 위치에 실행 가능한 버튼·링크·토글을 제공하라. 레이블은 연결 절차 시작, 설정 화면 이동, 실제 변경 등 클릭 시 일어나는 동작과 일치해야 한다.

현재 사용자가 조건을 충족할 수 있으면 그 동작으로 연결하라. 다른 사람의 조치가 필요하면 요청 수단이나 담당자를 안내하라. 결제나 외부 발송으로 이어지는 행동은 필요한 금액·대상·조건을 실행 전에 알려라.

## 7. 짧은 안내를 여백과 그룹으로 구성하라

서로 다른 안내는 한 항목씩 나누고 관련 컨트롤 가까이에 묶어라. 정렬, 여백, 의미에 맞는 아이콘 컴포넌트로 구조를 표현하라. 장식용 화살표·파이프·느낌표를 문구에 나열하는 경우에는 레이아웃과 상태 컴포넌트로 정리하라.

아이콘은 상태나 항목의 종류를 빠르게 구분하는 데 사용하라. 의미가 낯설거나 오류·제약을 전달해야 하면 짧은 텍스트를 함께 제공하라. 아이콘만 있는 버튼에는 접근 가능한 이름을 제공하고, 보조 설명은 관련 컨트롤에 연결하라. 필수 안내는 키보드와 터치에서도 확인할 수 있게 배치하라.

## 적용 예시

다음은 가상 제품의 상황별 예시다. 실제 제품의 동작과 조건을 확인한 뒤 적용하라.

| 상황 | 수정 전 | 수정 후와 판단 근거 |
| --- | --- | --- |
| 보고서 파일을 받는 버튼 | `확인` | `보고서 다운로드`. 클릭 결과를 레이블에 명시한다. |
| 첫 사용의 주소록 | `아직 연락처가 없습니다. 연락처를 추가하면 이곳에서 관리할 수 있습니다.` + `새로 만들기` | `주소록` 제목과 `연락처 추가` 버튼으로 구성한다. 빈 목록의 의미와 다음 행동이 드러난다. |
| 일반 알림 토글 | `끄면 알림이 중단됩니다. 이 스위치로 다시 켤 수 있습니다.` | `알림 받기` 레이블과 켜짐·꺼짐 상태로 표현한다. 같은 컨트롤로 전환하는 방법이 드러난다. |
| 영구 삭제 대화상자 | `선택한 파일을 처리할까요?` + `확인` | `파일 3개를 영구 삭제합니다. 복구할 수 없습니다.` + `파일 3개 삭제`. 대상·결과·복구 가능성을 전달한다. |
| 관리자가 변경하는 설정 | `이 기능을 사용할 수 없습니다.` | `관리자 권한이 필요합니다.` + `권한 요청`. 제한의 이유와 사용자가 가능한 행동을 제공한다. |
| 필터 적용 후 빈 목록 | `데이터가 없습니다.` | `조건에 맞는 주문이 없습니다.` + 활성 필터 + `필터 초기화`. 조건 때문에 결과가 비었음을 전달한다. |

## 작성·검토 절차

1. 화면의 사용자와 핵심 행동을 확인하고, 현재 상태와 실제 동작을 파악하라.
2. 제목부터 보조 설명까지 모든 문구를 주변 컨트롤과 함께 읽어라. 숨겨진 도움말, 접근 가능한 이름, 빈·오류·권한 상태도 확인하라.
3. 행동 레이블을 구체화하고 중복 설명을 정리하라. 필요한 결과와 제약은 관련 행동 가까이에 배치하고, 조건을 충족할 컨트롤을 제공하라.
4. 변경 전후를 비교해 대상·범위·비용·외부 영향·복구 조건·접근성이 보존되는지 확인하라. 실제 동작이 불명확하면 확인이 필요한 항목으로 남겨라.
5. 검토 결과에는 위치, 변경 전후, 판단 이유를 제시하라. 문구를 삭제했다면 의미를 전달하는 제목·상태·컨트롤을 근거로 명시하라. 필요한 설명이 없으면 해당 영역을 생략하라.

### 완료 기준

- [ ] 사용자가 레이블을 보고 행동과 대상을 예측할 수 있는가?
- [ ] 각 설명이 화면 구조에서 알 수 없는 판단 정보나 실수 예방 정보를 제공하는가?
- [ ] 중요한 결과, 권한 제약, 입력 조건과 복구 조건이 유지되는가?
- [ ] 기능을 사용할 조건을 충족할 수 있도록 가능한 행동이 제공되는가?
- [ ] 빈 상태의 원인과 다음 행동이 명확하며, 로딩·오류 상태와 구분되는가?
- [ ] 안내가 관련 컨트롤 가까이에 있으며, 키보드·터치·보조 기술로도 의미를 확인할 수 있는가?
