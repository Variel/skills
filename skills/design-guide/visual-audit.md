# 시각 감사: 전체 화면을 관찰하고 수정 결과를 검증하는 절차

이 문서는 에이전트가 렌더링된 UI의 문제를 넓게 발견하고, 근거를 확인한 뒤 수정 결과를 검증하는 절차를 정의한다. 화면 감사, 스크린샷 비교, UI 구현의 마감 검증과 부분 수정 전후에 사용하라. 시각적 선택 기준은 [visual-and-verification.md](visual-and-verification.md), 문구 기준은 [ui-copy.md](ui-copy.md)를 함께 적용하라.

**전체 관찰을 마친 뒤 수정에 착수하고, 수정 후에도 전체 관찰을 반복하라.** 사용자가 지적한 항목은 필수 확인 목록에 포함한다. 점검 중 발견한 다른 문제도 기록하고, 변경 범위는 사용자 목표와 실제 영향에 맞춰 정하라.

## 1. 감사 범위와 자료 준비

사용자가 이 화면에서 하려는 일, 대상 플랫폼, 주요 행동과 제품의 룩앤필을 짧게 기록하라. 기존 화면을 감사할 때는 현재 목적과 디자인 시스템을 기준으로 삼는다.

| 준비할 자료 | 확보 방법과 확인 사항 |
|---|---|
| 실제 표시 크기의 화면 | 뷰포트의 CSS 크기, 배율, 테마, 데이터·선택 상태를 기록한다. 폰트와 이미지가 로드된 안정된 화면을 촬영한다. |
| 전체 구조와 화면 구간 | 전체 페이지 이미지로 영역을 파악하고, 원래 표시 크기의 상단·중간·하단 이미지로 텍스트를 읽는다. 내부 스크롤 영역도 끝까지 확인한다. |
| 관련 상태 | 기본·선택·키보드 포커스·비활성 상태와 열리는 메뉴·모달을 확인한다. 데이터 영역은 실제로 제공되는 로딩·빈·오류 상태도 포함한다. |
| 크기·콘텐츠 변화 | 지원하는 좁은 화면과 넓은 화면, 긴 제목·큰 숫자·여러 줄 레이블, 첫 항목과 마지막 항목을 확인한다. 수정 영향을 받는 테마도 포함한다. |
| 수정 전후 비교 자료 | 같은 뷰포트·배율·데이터·스크롤 위치·상태로 촬영한다. 동적 데이터가 다르면 차이를 명시한다. |
| 상세 근거 | 의심 영역을 주변 맥락과 함께 크롭하고, 필요하면 computed style, 요소 크기, 대비 계산과 실제 조작 결과를 확보한다. |

점검할 화면·상태 조합은 제품의 주요 사용 경로와 변경 영향에 맞춰 선택하라. 관련 없는 조합은 적용 제외 이유를 기록한다. 스크린샷만 있는 경우에는 보이는 범위를 감사하고, 실행 환경이 필요한 항목은 미확인으로 남긴다. 폰트 로딩·레이아웃 안정화 전의 이미지는 최종 판정 근거로 사용하기 전에 다시 촬영하라.

## 2. 관찰 순서

### 1차: 전체 목적과 영역 파악

원본 화면을 실제 표시 크기로 보고, 처음 눈에 들어오는 요소와 예상되는 다음 행동을 기록하라. 이것은 이후 검증할 관찰이다. 상단 내비게이션, 제목·요약, 본문·목록, 보조 패널, 하단 행동, 고정·부유 요소처럼 화면을 영역으로 나눠 목록을 만든다.

비교 이미지의 강조 박스·화살표·정답 표시는 참고 정보로 취급하라. 각 화면을 독립적으로 훑은 뒤 표시된 변경점을 대조하라. 화면 목적, 영역별 정보와 관련 상태가 파악되면 다음 단계로 진행한다.

### 2차: 모든 영역을 순서대로 점검

상단부터 하단까지 각 영역에 아래 점검표를 적용하라. 작은 레이블과 보조 문구도 실제로 읽는다. 각 영역의 점검 상태를 `확인`, `문제`, `미확인`, `적용 제외` 중 하나로 기록하고, 문제가 있으면 발견 사항 ID를 연결한다. `확인`에는 관찰한 화면·상태를, `미확인`에는 필요한 자료를 명시하라.

| 관점 | 화면에서 확인할 내용 | 의심될 때 확인할 근거 |
|---|---|---|
| 목적과 위계 | 제목·핵심 정보·주 행동이 역할에 맞게 구별되는가? 보조 설명·가격·배지가 주 행동과 경쟁하는가? | 첫 시선 관찰, 축소 화면, 정보의 업무상 중요도를 대조한다. |
| 그룹과 여백 | 같은 묶음의 내부 간격보다 묶음 사이가 충분히 구별되는가? 레이블·오류 메시지가 올바른 대상 가까이에 있는가? | 인접 그룹의 간격과 정렬을 비교하고, 필요하면 레이아웃 값을 측정한다. |
| 정렬과 반복 | 행·열·텍스트 시작점과 베이스라인이 일관적인가? 첫 행과 마지막 행, 긴 값에서 정렬이 유지되는가? | 같은 역할의 요소를 가로·세로로 비교한다. 숫자 열과 텍스트 열은 각 읽기 목적을 고려한다. |
| 텍스트 가독성 | 작은 본문·단위·위치·헬퍼 텍스트를 읽을 수 있는가? Regular·Bold의 역할이 분명한가? 줄바꿈·행간·한글과 영문의 조합이 자연스러운가? | 실제 크기로 읽고, 적용된 서체·굵기·행간·너비를 확인한다. 확대 이미지는 원인 확인에 사용한다. |
| 아이콘 | 같은 역할의 아이콘이 획·채움·시각적 크기·정렬을 공유하는가? 선택 상태와 장식 스타일이 구별되는가? 숫자와 아이콘의 의미를 알 수 있는가? | 같은 계열의 아이콘끼리 비교하고, 레이블과 접근 가능한 이름을 확인한다. |
| 조작 가능 여부 | 버튼처럼 보이는 요소가 실제로 동작하는가? 링크·배지·선택 항목·정보 표시가 구별되는가? | 클릭·탭·키보드로 확인하고 역할·포커스·비활성 상태와 대조한다. |
| 색상과 대비 | 본문·보조 텍스트·플레이스홀더·아이콘이 각 배경에서 보이는가? 사진 위 컨트롤과 반투명 배지도 읽히는가? | 실제 전경·배경 조합과 상태별 대비를 측정한다. |
| 색상 외 단서 | 선택·오류·링크·차트의 의미를 색상 외에도 알 수 있는가? | 밑줄·체크·형태·패턴·텍스트를 확인하고 회색조 화면을 보조적으로 사용한다. |
| 경계와 가림 | 화면 끝·내부 스크롤 끝·고정 바 주변에서 내용과 포커스가 온전히 보이는가? 긴 콘텐츠와 열린 레이어가 잘리거나 겹치는가? | 실제 스크롤 끝, 좁은 화면, 확대·글자 크기 변경, 키보드 표시 상태를 확인한다. |
| 의미와 상태 | 제목·단위·가격 범위·상태·행동이 서로 일치하는가? 완료·오류·빈 상태에서 다음 행동을 이해할 수 있는가? | 문구 전문과 실제 데이터·제품 동작을 대조한다. 표시되지 않은 기능은 실행 환경에서 확인한다. |

영역 점검 기록 예시:

| 영역·상태 | 위계·그룹·정렬 | 텍스트·아이콘 | 행동·색상·대비 | 경계·의미·상태 |
|---|---|---|---|---|
| 상세 정보 / 기본 | 확인: 제목·속성·본문 구분 | 문제: V-02 | 미확인: 링크 동작 | 확인: 단위·레이블 |
| 하단 행동 / 좁은 화면 | 확인: 가격·주 행동 구분 | 확인: 문구 표시 | 문제: V-03 | 미확인: 스크롤 끝 |

### 3차: 같은 역할과 서로 다른 상태 비교

영역별 점검이 끝나면 버튼끼리, 링크끼리, 보조 텍스트끼리, 목록 행끼리 묶어 다시 비교하라. 동일한 역할의 표현 차이와 서로 다른 역할의 외형 유사성을 모두 찾는다. 같은 요소의 기본·선택·포커스·비활성 상태도 비교하라.

예를 들어 아이콘 하나가 채워져 있으면 선택 상태인지 확인한다. 테이블의 한 행만 볼 때 정렬이 좋아 보여도 여러 행의 긴 값과 짧은 값을 비교한다. 가격의 숫자와 단위는 각각 읽히는지, 서로 올바른 묶음으로 보이는지 함께 확인한다.

### 4차: 관찰에 맞는 검증 실행

| 검증 | 확인할 질문 | 판정 범위 |
|---|---|---|
| 축소·흐림 테스트 | 세부 텍스트를 읽기 어려워져도 주요 영역과 행동을 찾을 수 있는가? | 시각적 위계의 보조 근거다. 실제 글자 가독성과 접근성은 별도로 확인한다. |
| 회색조 확인 | 색상 차이가 줄어도 상태와 링크를 구별할 수 있는가? | 색상 외 단서를 찾는 보조 수단이다. 모든 색각 특성을 재현하는 검사는 아니다. |
| 요소 제거 비교 | 특정 테두리·배경·설명을 가려도 그룹·의미·행동을 이해할 수 있는가? | 제거할 요소의 기능을 검증한다. 이미지·브랜드·설명의 가치는 해당 화면의 목적과 함께 판단한다. |
| 실제 크기 읽기 | 크롭을 확대하지 않은 화면에서 작은 텍스트도 읽을 수 있는가? | 확대본에서 읽힌다는 사실은 실제 크기의 가독성을 보장하지 않는다. |
| 전체 재관찰 | 주목한 문제 외에 다른 영역에도 확인할 문제가 남아 있는가? | 기록한 전체 영역과 점검표를 다시 순회한다. |

### 측정과 동작 확인

발견 사항의 근거를 다음처럼 구분하라.

- **관찰:** 이미지에서 직접 확인한 텍스트, 정렬, 색상 차이, 잘림과 상태다. 작은 차이를 확신하기 어려우면 원본 해상도 크롭으로 다시 확인하라.
- **측정:** computed style, 실제 적용된 폰트, 요소 크기, 대비 계산처럼 재현 가능한 값이다. 스크린샷의 픽셀은 배율을 확인해야 CSS px로 환산할 수 있다.
- **동작 확인:** 클릭·키보드·스크롤·글자 크기 변경 등 실행 결과다. 정지 화면만으로 클릭 가능 여부, 스크롤 끝의 가림, 접근 가능한 이름을 확정할 수 없다.
- **가설:** 위계가 혼란스러워 보이거나 조작 대상으로 오인할 가능성처럼 추가 확인이 필요한 해석이다. 필요한 확인 방법을 함께 기록하라.

미세한 간격·획 차이는 크롭을 2~4배 확대하거나 레이아웃·픽셀 값을 확인하라. 픽셀 경계를 비교할 때는 nearest-neighbor 확대를 사용할 수 있다. 래스터 이미지의 색은 압축·안티앨리어싱의 영향을 받으므로, 대비는 가능한 경우 원본 스타일의 전경·합성 배경값으로 계산하라. 이미지에서 구한 값은 측정 방법과 한계를 명시한다.

접근성 측정 기준:

| 대상 | 기준과 적용 범위 |
|---|---|
| 일반 텍스트 | 배경과 4.5:1 이상. 플레이스홀더와 보조 설명도 포함한다. |
| 큰 텍스트 | 배경과 3:1 이상. CSS 기준 24px 이상 또는 Bold 약 18.67px 이상이다. 네이티브 앱은 플랫폼 단위·배율을 확인하고, 분류가 불명확하면 4.5:1을 적용한다. |
| 비텍스트 시각 단서 | 컨트롤·상태 식별과 그래픽 이해에 필요한 부분은 인접 색과 3:1 이상이다. 버튼의 글자 대비와 버튼 식별에 필요한 부분의 대비를 각각 확인한다. |
| 사진·그라디언트·투명 배경 | 텍스트나 아이콘 바로 아래의 실제 합성 배경을 확인한다. 이미지 변경·크롭·테마에 따라 가장 불리한 배경도 검증한다. |
| 예외 | 비활성 컨트롤, 장식, 로고와 수정하지 않은 브라우저 기본 컨트롤 등은 해당 성공 기준의 적용 범위를 확인한다. 모든 테두리·그림자에 일률적으로 3:1을 요구하지 않는다. |

근거: [WCAG 텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [색상 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html).

웹의 읽기 영역은 사용자 텍스트 간격 변경도 확인하라. 행간 1.5배, 단락 뒤 간격 2em, 자간 0.12em, 단어 간격 0.16em을 해당 언어에 적용할 수 있는 범위에서 동시에 설정했을 때 내용과 기능이 유지되는지 검증한다. 이는 사용자 설정을 수용하는 검사이며, 기본 스타일의 권장 수치와 구분한다. [WCAG 텍스트 간격](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)

## 3. 수정과 재검증

전체 점검 기록을 완료한 뒤 발견 사항을 사용자 영향과 근거에 따라 정렬하라. 실제 접근성 실패·작업 차단은 필수 수정, 이해·탐색·읽기를 방해하는 문제는 개선 권장, 브랜드 취향에 따른 대안은 선택 제안으로 구분한다. 제품의 사용 조건에서 발생하는지 확인하고, 같은 원인의 여러 증상은 묶어서 수정하라.

수정은 원인별로 묶고 다음을 반복한다.

1. 해결할 문제와 기대하는 결과를 명시한다. 예: 보조 텍스트의 가독성을 확보하면서 제목과의 위계를 유지한다.
2. 변경한 영역을 동일 조건으로 다시 촬영하고, 필요한 대비·크기·동작을 다시 확인한다.
3. 인접 영역과 같은 토큰을 사용하는 다른 컴포넌트도 확인한다. 서체·굵기·행간 변경은 줄바꿈·높이·스크롤·고정 바와의 관계까지 확인한다.
4. 전체 화면을 실제 크기로 다시 보고, 2차 점검표의 모든 관점을 재확인한다. 해결한 항목, 남은 항목과 새로 발견한 항목을 갱신한다.

수정 후 새로운 근거가 없다면 동일한 검사를 반복하기보다 완료 조건을 확인하라. 관찰 결과가 초기 가설과 다르면 그 결과에 맞춰 판정을 수정한다.

## 4. 보고 형식과 완료 조건

발견 사항은 다른 사람이 같은 화면에서 재확인할 수 있도록 작성하라.

```text
V-01 [필수/권장/제안] 짧은 문제 설명
위치·조건: 화면 경로, 영역, 뷰포트, 테마, 상태
근거: 관찰 / 측정 / 동작 확인 / 가설과 구체적 내용
사용자 영향: 어떤 정보·행동을 읽거나 구별하기 어려운가
조치: 수정 내용 또는 추가 확인 방법
재검증: 수정 후 결과, 남은 문제, 화면·크롭·코드 위치 링크
```

최종 보고에는 주요 발견 사항과 함께 점검한 화면·상태, 해결·잔여 항목, 미확인 범위와 이유를 남긴다. 정적 이미지만 확인했다면 실행 상태를 포함한 감사를 완료했다고 보고하지 않는다.

- [ ] 대상 화면의 모든 영역과 관련 상태에 점검 기록이 있다.
- [ ] 원래 요청한 항목과 별도로 발견한 문제를 모두 처리하거나 잔여 항목으로 기록했다.
- [ ] 대비·치수·동작에 대한 확정적 주장에는 측정 또는 실행 근거가 있다.
- [ ] 수정 전후의 조건을 맞춰 비교했고, 주변 영역과 같은 역할의 컴포넌트도 확인했다.
- [ ] 전체 화면을 재점검했으며, 새로 생긴 줄바꿈·잘림·위계·상태 문제가 없다. 남은 문제가 있다면 명시했다.
- [ ] 미확인 항목을 통과로 처리하지 않았고, 필요한 후속 확인을 기록했다.
