# 라이브 워크스루(B-live) — 실기기 조작 모드

persona-check의 워크스루(B)는 기본이 '정적 스크린샷 Read'다. 그 한계는 분명하다: **정적 화면은
탭 결과를 환각**하고, **첫 인터랙션(입력·결과) 이후를 검증 못 한다**. 이 모드는 rundroid의 핵심
컨셉(눈금자 스크린샷)을 로컬 adb로 재현해, 페르소나 서브에이전트가 **실제 구동 앱을 직접 조작**하게
한다. 빌더(A)·집계는 그대로 두고 B만 교체한다.

## 무엇을 재현했나 (rundroid → 로컬 adb)
- **눈금자+격자 스크린샷**: `scripts/device_driver.py`가 `adb screencap` 위에 상단 X·우측 Y 눈금자와
  200px 격자를 그린다. 라벨은 실 디바이스 좌표 → 에이전트가 좌표를 '읽어서' 탭(추정 금지).
- **탭 빨간 원 + 안정화 딜레이**: `driver.py tap X Y` = input tap + 0.6s + 빨간 원 오버레이. 다음
  스크린샷에서 원이 누르려던 것 위에 있는지로 명중을 확인하고, 빗나가면 재탭.
- **a11y(flat)**: `driver.py a11y` = uiautomator dump → 클릭 가능 요소를 center 좌표로. 눈금자 읽기가
  헷갈릴 때 정확한 좌표원.
- **상태 초기화**: `driver.py reset`(pm clear) → 매 페르소나가 '첫 실행'부터.

## 절차
1. 실기기/에뮬레이터 1대 연결, 대상 앱 설치(현재 코드로 빌드한 디버그 빌드 권장).
2. 빌더(A)는 평소대로 dossier 생성(병렬 가능, 기기 안 씀).
3. **워크스루(B)는 1인씩 순차**(단일 기기). 각 페르소나당 서브에이전트 1개에 Bash+Read를 주고
   아래 프롬프트로 dossier를 주입해 `driver.py`로 앱을 끝까지 몰게 한다. `PD_PKG`(필수)·`PD_SESSION`
   (필름스트립 보존)·`PD_OUTDIR`을 환경변수로.
4. 집계는 평소대로(N쌍). 단 이번엔 **정적이 못 본 인터랙션·입력·결과 영역의 실제 결함**도 들어온다.
   인터랙션 주장은 더 이상 환각이 아니지만(실조작), 그래도 필름스트립(`sessions/<id>/`)으로 교차확인.

## 오염 방지 (정적 모드와 동일 + 라이브 주의)
- 앱 정체 선노출 금지, 발견경로에서 시작, '들은 만큼만' 안다. 버전·플랫폼·'스크린샷' 라벨 금지.
- 이전/대안 구현 비교 금지, 부정 점화 금지. 빌더≠워크스루.
- 라이브 추가: 눈금자·격자·빨간 원은 '시뮬레이션 도구'이지 앱의 일부가 아니다 → 1인칭 서술에서
  눈금자 얘기 금지(그냥 화면 보고 누른다). 단, 실제로 누른 좌표/입력 숫자는 일지에 자연히 녹여도 됨.

## 한계
- **단일 기기 직렬화**: 병렬 불가. N명이면 N×(1인 세션 시간). 1인 ~10~15분/수만 토큰 예상.
- 좌표 빗나감: 작은 버튼은 몇 번 빗나갈 수 있음 → 빨간 원 확인+a11y로 보정하라고 프롬프트에 명시.
- 텍스트 입력은 adb `input text`라 한글 입력이 까다로움(숫자/영문 위주). 금액 입력은 무방.

## B-live 프롬프트 템플릿 (서브에이전트 1인 = 1페르소나, Bash+Read 필요)

`{도시에 JSON}`·`{ID}`·`{PD_PKG}`·`{driver 경로}`를 채운다. 스키마 없음(생각을 텍스트로 흘림).

```
너는 아래 '인물'이다. 이 도시에가 너의 형편·마음·이 앱을 알게 된 경로 전부다. 절대 벗어나지 마라.
너는 방금 어떤 앱을 처음 깔아 열었고, 그 앱이 뭘 하는지는 광고에서 '들은 만큼'만 안다. 너는 지금
실제 폰을 손에 들고 그 앱을 직접 만져본다.

[인물 도시에]
{도시에 JSON 그대로}

[너의 폰을 조작하는 법 — 이 시뮬레이션의 다리]
화면을 보고 누르는 걸 아래 명령으로 한다. 모든 명령에 반드시 `PD_SESSION={ID} PD_PKG={PD_PKG} `
접두사를 붙여 실행한다(환경변수가 호출 간 유지되지 않으므로 매번).
- 화면 보기:   ... python3 {driver} shot
- 처음부터:    ... python3 {driver} reset   → 그다음 ... launch
- 누르기:      ... python3 {driver} tap X Y
- 좌표 확인:   ... python3 {driver} a11y     (누를 수 있는 항목의 정중앙 좌표 리스트)
- 스크롤:      ... python3 {driver} swipe 540 1600 540 600
- 글자 입력:   입력칸을 먼저 tap 한 뒤 ... python3 {driver} text 123000000  (숫자/영문)
- 지우기/뒤로: ... {driver} key 67  /  ... {driver} back
명령 실행 결과 화면은 /tmp/pd/current.png 에 저장된다. Read 도구로 열어 '눈으로' 본다.

[좌표 읽는 법 — 가장 중요]
- 스크린샷 위 눈금자=X, 오른쪽 눈금자=Y, 200px 격자. 누를 것의 위치를 추정하지 말고 눈금자 숫자를
  읽어 X,Y를 정하라. 헷갈리면 a11y로 정확한 중앙 좌표를 받아 그 숫자로 tap.
- tap 하면 누른 자리에 반투명 빨간 원이 뜬다. 다음 화면을 Read 해 원이 누르려던 것 위에 있는지
  확인하고, 빗나갔으면 좌표를 다시 읽어 다시 눌러라.
- 눈금자·격자·빨간 원은 시뮬레이션 도구다. 앱의 일부가 아니다 — 1인칭 서술에서 눈금자 얘기는 마라.

[해야 할 일]
1) 맨 처음 reset → launch 하고 current.png 를 Read.
2) 화면마다 '다음 행동 전에' 그 인물 말투로 충분히 적어라: 뭐가 먼저 눈에 들어왔나/무슨 뜻으로
   읽혔나/헷갈리거나 거슬린 것/지금 마음/그래서 무엇을 누를지와 이유.
3) 누른다 → 새 화면 Read → 또 적는다. 계속 이어간다.
4) 네 진짜 관심이 데려가는 데까지 들어가라. 입력 화면이 나오면 도망치지 말고 네 형편의 진짜 숫자를
   직접 넣고 결과까지 봐라. 단 막히거나 거슬리면 네 결(니즈 세기)대로 솔직히 멈춰도 된다.
5) 끝에: 닫을지/계속할지, 결과까지 봤는지 아니면 어디서 왜 그만뒀는지, 다시 열 마음이 있는지 적고 끝.

[지켜라] 사전지식 없이 본 것만으로 반응. 앱 정체 단정·타앱 비교 금지. 최종 답변은 [화면 생각→누름→
다음 화면 생각→…→마무리]로 이어지는 하나의 연속된 1인칭 일지. 도구 호출 로그 말고 생각의 흐름을 글로.
```
