# 오염 방지 — 나쁨 → 교정

전부 실패에서 나온 것. 평가자에게 몰라야 할 걸 흘리거나 해야 할 추론을 건너뛰면 반응이 망가진다.

1. **앱 정체 선노출**
   - 나쁨: "[이 앱은 ○○ 계산해주는 앱]".
   - 발견·기대 형성이 사라진다 → 첫 화면이 기대를 충족/배신했는지 못 본다.
   - 교정: 발견 경로에서 시작, "들은 만큼만" 안다.

2. **메타 라벨**
   - 나쁨: "v3 안드로이드 스크린샷".
   - 사용자가 알 리 없는 정보 → 평가를 메타로 비튼다.
   - 교정: "그냥 어떤 앱 화면".

3. **구현 비교 (가장 교묘)**
   - 나쁨: 스키마에 `"자동진행 대비 어떤가"`.
   - 증상: "휙 넘어가면 당황, 한 번 더 확인하니 안심" → *이전 구현을 알았다는 증거*.
   - 없던 대안의 존재를 주입해 오염. 교정: 비교 항목 자체를 두지 않는다. 반응은 본 것만으로.

4. **부정 점화**
   - 나쁨: "억지로 관심 있는 척 말라" → '관심'이 점화돼 오히려 생긴다.
   - 교정: 불필요한 단서를 아예 언급 안 함.

5. **빈칸 미충전**
   - 나쁨: "실제 형편에서 판단하라" — 형편이 카드에 없는데.
   - 모델이 즉석에서 대충 만들고 반응 → 근거 얕음.
   - 교정: 빌더가 *반응 전에* 형편·니즈를 추론해 확정.

6. **추론 혼합**
   - 나쁨: 한 에이전트가 "인물 만들기 + 평가" 동시 → 자기가 지어낸 설정에 끼워맞춤.
   - 교정: 빌더(A) → 워크스루(B) 분리. B는 인물을 안 만들어서 더 날것.

7. **워크스루 스키마**
   - 나쁨: B가 JSON 필드에 사후 요약 → 화면 안 따라가고 합리화만.
   - 교정: 스키마 없이 화면마다 그 자리에서 생각을 흘리고, 직전 선택이 다음 Read를 정함(미리 다 못 읽음 = 순차).

## 한계
정적 스크린샷은 "눌렀는데 반응 없다" 같은 탭 결과를 환각한다. 인지·동기(첫인상·위계·카피·발견기대)는
신뢰하되, 탭 후 전환·로딩·에러·입력은 실제 구동으로 검증. 집계 시 인터랙션 주장은 환각 가능성 표시.
