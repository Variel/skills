# Persona Walkthrough Simulation

실제 인구에 근거한 페르소나가 제품 화면을 처음 써보게 해, 첫인상과 마찰·이탈 지점을 찾는다.

## 2단계
- **빌더(A)**: 페르소나 카드의 빈칸(형편·니즈·발견경로→설치)을 추론해 채운다. 화면은 안 본다. → 도시에(dossier).
- **워크스루(B)**: A의 도시에를 물려받아 화면을 하나씩 보며 처음 써본다. 스키마 없이 화면마다 생각을 텍스트로 흘리고, 직전 선택이 다음 화면을 정한다.
- **집계**: 별도 에이전트가 N쌍을 모아 "화면 결함"과 "발견경로-기대 불일치"를 나눠 보고한다.

만드는 추론과 쓰는 추론을 한 에이전트에 섞으면 자기가 지어낸 설정에 끼워맞춰 꼬여서 분리한다.

프롬프트·스키마 원본(런타임 무관)은 `references/prompts.md`. Claude Code는 그걸 담은
`scripts/two_stage_sim.js`를 Workflow로 실행하고, Codex 등 Workflow가 없는 환경은 `prompts.md`를
서브에이전트나 순차 실행에 그대로 넣어 쓴다.

## 입력 (제품마다 채움)
- **페르소나 출처**: 근거 있는 샘플. 한국 타깃은 `references/k-persona.md`를 따라 뽑은 뒤 `split_personas.py`로 1인 1파일. 보통 인-마켓 편향.
- **제품 도메인 한 줄**: 빌더가 니즈를 생성할 영역. 앱 정체는 직접 노출하지 않는다.
- **발견경로 레퍼런스**: 그 제품군이 실제로 광고·입소문·추천되는 말투.
- **화면 + 분기 지도**: 실제 구동 캡처 + "선택→다음 화면" 링크.

## 절차
1. `references/k-persona.md`로 샘플 → `split_personas.py`로 분리.
2. 실제 구동 → 화면 캡처 + 분기 지도.
3. `two_stage_sim.js` 입력 3곳 채워 `Workflow` 실행.
4. 집계 → 보고서·일지 저장.

## 오염 방지 (항상)
1. 앱 정체 선노출 금지 — 발견 경로에서 시작, 들은 만큼만 안다.
2. 버전·플랫폼·"스크린샷" 라벨 금지.
3. 이전/대안 구현과 비교 금지 — 없던 대안을 주입해 오염.
4. 부정 점화 금지("~척 말라" 류).
5. 빈칸은 빌더가 먼저 채운다(반응 전).
6. 빌더 ≠ 워크스루(다른 에이전트).
7. 워크스루엔 스키마 금지 — 화면마다 그 자리에서 생각을 흘리고 직전 선택이 다음을 정함.

## 한계
- 정적 스크린샷은 탭 결과를 환각한다 — 인터랙션은 실제 구동(rundroid 등)으로 검증.
- 일지 누락·혼입 점검 후 손상분 제외·명시.

## 번들
- `references/prompts.md` — 프롬프트 3개 + 스키마 2개 + 채울 입력 4개 (런타임 무관 원본)
- `scripts/two_stage_sim.js` — 위 프롬프트를 담은 Claude Code Workflow 구현, `scripts/split_personas.py`
- `references/k-persona.md` — 페르소나 샘플링(k-persona), 1단계로 먼저 사용
- `references/anti-contamination.md`, `references/worked-example.md`
