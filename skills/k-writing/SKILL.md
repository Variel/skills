# K-Writing: 독자에게 필요한 내용을 자연스러운 한국어로 작성하세요

이 스킬은 문서의 내용, 구성, 표현과 최종 검증을 하나의 절차로 처리합니다. 제작 과정이 아니라 현재 유효한 내용을 남기며, 한국어 문서는 독자가 실제로 사용하는 어휘와 문장으로 작성합니다.

## 핵심 원칙

1. **독자와 목적을 먼저 확정합니다.** 독자가 글을 읽은 뒤 무엇을 이해하거나 수행해야 하는지 한 문장으로 정합니다.
2. **제작 지침과 문서 내용을 분리합니다.** 피드백과 대화는 결과물을 만드는 데 사용하고, 산출물에는 독자에게 필요한 최종 상태만 남깁니다.
3. **내용 편집을 먼저 끝냅니다.** 범위, 구조, 요구사항과 결론을 확정한 뒤 한국어 표현을 다듬습니다.
4. **장르에 맞는 형식을 사용합니다.** 불릿과 볼드는 금지 대상이 아닙니다. 빠른 탐색이 중요한 글에는 적극적으로 사용하고, 연속적인 설명이 필요한 글에는 문단을 사용합니다.
5. **평이하고 구체적으로 씁니다.** 의미를 보태지 않는 대조, 비유, 경구와 과장된 제목을 기본적으로 사용하지 않습니다.
6. **의미를 보존하며 표현만 다듬습니다.** 수치, 고유명사, 인용, 요구사항, 예외, 기본값과 핵심 개념을 보호합니다.
7. **완성된 산출물을 먼저 전달합니다.** 사용자가 요청하지 않았다면 제작 과정, 진단 코드와 내부 검수 결과를 덧붙이지 않습니다.

## 참조 자료를 읽는 순서

작업을 시작할 때 다음 자료를 필요한 범위까지 읽습니다.

1. `references/document-genre-formatting.md`: 장르별 문서 구조, 불릿과 볼드 사용 기준입니다.
2. `references/korean-style-rules.md`: 번역투, 과장된 AI 어투와 부자연스러운 표현을 판별하고 고치는 기준입니다.
3. `references/fidelity-checklist.md`: 최종 문서에서 내용과 구조가 보존됐는지 확인하는 기준입니다.

길거나 공개되는 한국어 문서, 보고서, 제안서와 스펙은 세 자료를 모두 적용합니다. 짧은 답변이나 간단한 수정은 해당하는 규칙만 적용하되 핵심 원칙은 생략하지 않습니다.

## 스크립트 경로

`SKILL_DIR`은 현재 로드한 `SKILL.md`가 있는 디렉터리의 절대 경로입니다. 스크립트는 작업 디렉터리 기준 상대 경로로 찾지 말고 `${SKILL_DIR}/scripts/...`의 절대 경로로 실행합니다. 참조 자료도 `SKILL_DIR`을 기준으로 읽습니다.

## 작성 절차

### 1. 독자와 문서의 역할을 정합니다

- 예상 독자, 독자의 배경지식과 필요한 행동을 정합니다.
- 문서 종류를 요약, 브리핑, 절차, 비교, 스펙, 보고서, 설명문, 발표문 또는 기타로 분류합니다.
- 제목은 문서의 실제 내용을 직접 나타내야 합니다. 분위기나 인상을 만들기 위한 문구를 제목으로 사용하지 않습니다.

완료 기준: 독자, 목적과 문서 종류를 각각 한 문장으로 설명할 수 있습니다.

### 2. 입력을 세 범주로 나눕니다

1. **독자에게 필요한 내용**은 산출물에 직접 적습니다.
2. **제작 지침**은 구조와 표현에 반영한 뒤 산출물에서 제거합니다.
3. **제작 과정의 잔여물**인 대화 이력, 중간 판단, 폐기한 접근과 수정 경위는 독자에게 필요할 때만 남깁니다.

완료 기준: 모든 입력 정보가 세 범주 중 하나에 속하며, 요구사항과 제약이 독자용 내용에서 빠지지 않았습니다.

### 3. 현재 유효한 상태를 직접 씁니다

- “A가 아니라 B여야 한다”라는 교정에서는 현재 기준인 B를 직접 설명합니다.
- 금지는 가능한 행동과 판단 기준으로 바꿉니다.
- 이전 표현과 변경 이력은 운영이나 호환성 이해에 필요할 때만 남깁니다.
- “요청에 따라”, “요구사항을 반영하여” 같은 제작 과정 설명은 제거합니다.
- 안전 경고, 호환성, 지원 범위, 필수 조건, 흔한 오해와 교육용 반례처럼 독자의 판단에 필요한 부정과 제약은 남깁니다.

완료 기준: 대화를 보지 않은 독자도 문서만으로 현재 기준과 필요한 행동을 이해하며, 중요한 위험과 적용 조건을 놓치지 않습니다.

### 4. 장르에 맞게 정보를 배열합니다

`references/document-genre-formatting.md`를 적용합니다.

- 빠르게 훑어야 하는 요약, 브리핑, 체크리스트와 절차에는 불릿을 사용합니다.
- 여러 항목을 비교하거나 상태를 확인해야 할 때는 표나 목록을 사용합니다.
- 논리와 맥락을 따라 읽어야 하는 설명문, 보고서 본론과 서사에는 문단을 사용합니다.
- 볼드는 핵심 결론, 항목명과 행동처럼 탐색에 필요한 짧은 구절에만 사용합니다.

완료 기준: 형식이 장르와 독서 방식에 맞으며, 불릿과 볼드가 정보 구조를 실제로 드러냅니다.

### 5. 한국어 문체를 다듬습니다

`references/korean-style-rules.md`를 적용합니다.

- 번역투, 불필요한 피동, 형식명사와 추상 명사 연쇄를 구체적인 한국어 문장으로 바꿉니다.
- 제목과 문장을 불필요한 대조나 선언으로 꾸미지 않습니다.
- 독자가 실제로 쓰지 않는 어휘, 문맥에 맞지 않는 업계 은유와 과도한 비유를 일반적인 표현으로 바꿉니다.
- 원문의 격식과 전문 용어를 유지합니다. 자연스럽게 보이기 위해 말투를 임의로 낮추거나 전문 용어를 일상어로 바꾸지 않습니다.

완료 기준: 각 문장을 소리 내어 읽었을 때 일반적인 한국어 문장으로 이해되며, 꾸민 표현을 제거해도 정보가 줄지 않습니다.

### 6. 필요한 경우 결정적 검사를 실행합니다

길거나 공개되는 한국어 문서는 다음 명령으로 주의할 표현을 점검합니다.

```bash
python3 "${SKILL_DIR}/scripts/lint_korean.py" <문서경로> --genre <summary|briefing|procedure|spec|report|explanation|presentation>
```

검사 결과는 자동 수정 명령이 아니라 검토 후보입니다. 인용문, 고유명사, 법률 용어와 해당 분야에서 실제로 사용하는 기술 용어에는 기계적으로 적용하지 않습니다.

완료 기준: 경고를 각각 유지, 수정 또는 예외로 판정했고, 단순히 검사 통과를 위해 의미를 바꾸지 않았습니다.

### 7. 내용 편집본과 문체 수정본을 대조합니다

내용과 구조를 확정한 초안을 기준본으로 저장한 뒤 한국어 표현만 다듬습니다. 두 파일이 있으면 결정적 검사를 실행합니다.

```bash
python3 "${SKILL_DIR}/scripts/verify_fidelity.py" <내용편집본> <문체수정본>
```

제목 변경처럼 내용 편집 단계에서 의도적으로 확정한 변경은 기준본에 이미 반영돼 있어야 합니다. 검사 결과가 있으면 해당 항목을 원문과 직접 대조하고, 의도하지 않은 변경만 국소적으로 복원합니다.

`references/fidelity-checklist.md`에 따라 다음 사항도 직접 확인합니다.

- 사실, 주장, 수치, 날짜와 고유명사가 유지됐습니다.
- 요구사항, 예외, 기본값과 사용자의 행동이 빠지지 않았습니다.
- 직접 인용, 링크, 제목, 표와 목록의 관계가 훼손되지 않았습니다.
- 원문에 없던 주장, 인과관계, 마케팅 표현과 비유가 추가되지 않았습니다.
- 문서 전체에서 제목, 용어, 어조와 설명 수준이 일관됩니다.

완료 기준: 보호 항목이 모두 확인됐으며, 남은 변경은 문서 목적이나 한국어 표현을 개선합니다.

## 후속 수정

사용자가 특정 문단, 어조, 형식 또는 표현을 다시 요청하면 전체 문서를 다시 쓰지 않습니다. 요청받은 범위와 그 변경으로 직접 영향을 받는 연결 부분만 수정한 뒤, 보호 항목을 다시 확인합니다.

사용자가 변경 요약을 요청했다면 완성된 산출물을 먼저 제시하고, 변경 요약을 별도 구역에 작성합니다.

## 최종 검증

1. 문서를 처음 읽는 독자가 목적과 결론을 이해할 수 있습니까?
2. 모든 문장이 현재 유효한 정보나 행동을 전달합니까?
3. 불릿, 표와 볼드는 장르에 맞게 탐색을 돕습니까?
4. 제목과 문장에 불필요한 대조, 경구, 과장과 비유가 남아 있습니까?
5. 일상적으로 사용하지 않는 어휘나 기계적인 직역이 남아 있습니까?
6. 수치, 인용, 고유명사, 요구사항, 예외와 기본값이 보존됐습니까?
7. 제작 과정과 내부 검수 정보가 불필요하게 노출됐습니까?
8. 산출물이 하나의 목적과 목소리를 가진 독립적인 문서로 읽힙니까?

모든 항목을 확인한 뒤 완성된 산출물 자체를 전달합니다.
