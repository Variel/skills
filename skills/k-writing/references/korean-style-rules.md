# 자연스러운 한국어 표현 기준

이 문서는 독자가 실제로 사용하는 한국어와 문서의 목적을 기준으로 표현을 검수합니다. 특정 표현을 무조건 금지하지 않고, 정보 전달에 필요한지와 해당 분야에서 통용되는지를 판단합니다.

## 1. 불필요하게 있어 보이는 문장을 피합니다

정보를 직접 전달할 수 있는데도 대조, 경구, 비유와 추상어로 문장을 꾸미면 독자는 표현을 해석한 뒤 내용을 다시 찾아야 합니다. 꾸민 표현을 제거해도 정보가 그대로라면 직접적인 문장으로 바꿉니다.

### 대조 공식

`A한 것은 B가 아니라 C다`, `A가 아니라 B`, `A를 넘어 B로` 같은 구조는 실제 대조가 핵심일 때만 사용합니다. 차이가 중요하지 않거나 단순한 강조를 위해 만든 대조라면 C를 직접 설명합니다.

- 피함: “중요한 것은 속도가 아니라 방향입니다.”
- 권장: “사용자가 완료해야 하는 행동을 먼저 정합니다.”

### 읽는 순서를 연출하는 도입

“먼저”로 시작하는 제목, “결론부터 말하면”으로 시작하는 제목이나 문장은 실제 순서 안내가 필요할 때만 사용합니다. 결론을 바로 쓰면 되는 문서에서는 해당 도입을 제거합니다.

- 피함: “결론부터 말하면: 자동화의 새로운 기준”
- 권장: “자동화 범위와 승인 조건”

### 대칭 문장

`A는 ~하는데 B는 ~합니다`처럼 두 절을 기계적으로 맞추지 않습니다. 실제 비교라면 같은 비교 기준을 명시하고, 비교가 아니라면 각 사실을 독립적으로 설명합니다.

### 과장된 제목과 문장

마케팅 문구로 사용하기에도 과장되거나 어색한 표현을 쓰지 않습니다. “새로운 시대를 여는”, “판을 바꾸는”, “보이지 않는 혁명”, “조용히 무너지는”처럼 정보를 제공하지 않는 문구는 구체적인 대상과 변화로 교체합니다.

## 2. 문맥 없는 은유와 업계식 표현을 피합니다

일반적인 뜻보다 특정 업계의 은유로 쓰이는 동사는 독자가 같은 관용 표현을 알고 있을 때만 사용합니다.

- `닫는다`: 실제로 문, 연결, 세션, 창 또는 쟁점을 종료하는 뜻일 때 사용합니다. “격차를 닫는다”처럼 영어 표현을 옮긴 문장에서는 “격차를 줄인다”라고 씁니다.
- `박습니다`: 못이나 도장을 실제로 박는 상황, 또는 해당 독자층에서 충분히 통용되는 구어적 표현일 때만 사용합니다. “코드에 박습니다”는 “코드에 명시합니다”로 씁니다.
- `흐름`, `축`, `레이어`, `파이프라인`: 해당 분야의 기술 용어일 때는 유지합니다. 일반 문서에서 단지 전문적으로 보이기 위해 사용했다면 구체적인 단계나 관계로 씁니다.

사용자가 요구하지 않은 비유를 새로 만들지 않습니다. 설명에 비유가 꼭 필요하다면 무엇을 설명하는지 먼저 직접 서술하고, 비유가 실제 이해를 단축하는지 확인합니다.

## 3. 직역어를 문맥에 맞게 고칩니다

영어 단어를 한국어 사전의 첫 번째 대응어로 치환하지 않습니다. 원문에서 수행하는 기능을 파악한 뒤 일반적인 한국어 표현을 선택합니다.

### silently

소리의 부재가 아니라 경고나 표시 없이 동작한다는 뜻이라면 `조용히`라고 번역하지 않습니다.

- `silently fails` → “오류를 알리지 않고 실패합니다”, “실패해도 표시되지 않습니다.”
- `silently skips` → “안내 없이 건너뜁니다.”
- 실제 음향이나 발화가 없는 상황에서는 “조용히”를 사용할 수 있습니다.

### 문맥에 따라 달라지는 한자어

`계약`, `경계`, `위생`은 일반적인 뜻이나 분야별 기술 용어로 필요할 수 있으므로 금지어가 아닙니다. 다만 영어 개념을 기계적으로 옮기거나 전문적으로 보이게 만드는 용도로 사용하지 않습니다.

- `contract`: 법률 계약이나 API·인터페이스 계약처럼 독자가 익숙한 용어라면 `계약`을 유지합니다. 단순한 약속이나 입출력 조건이라면 `규칙`, `조건`, `입출력 형식`처럼 실제 뜻을 씁니다.
- `boundary`: 공간·수학·보안 경계처럼 실제 경계를 뜻하면 유지합니다. 모듈 책임이나 실행 범위를 뜻하면 `책임 범위`, `실행 범위`, `구분`처럼 구체적으로 씁니다.
- `hygiene`: 보건·식품·치과 위생에서는 유지합니다. 텍스트나 코드 정리에서는 `정리`, `정규화`, `오염 문자 제거`, `관리 원칙`처럼 실제 작업을 씁니다.

## 4. 대중이 실제로 사용하는 어휘를 선택합니다

사전에 등재됐다는 이유만으로 어휘를 사용하지 않습니다. 해당 독자층의 기사, 안내문, 제품 문서와 일상적인 문어에서 실제로 통용되는지 판단합니다.

다음 중 하나에 해당하면 더 일반적인 표현을 찾습니다.

- 뜻을 설명하기 위해 다시 쉬운 말로 풀어야 합니다.
- 같은 분야의 독자가 검색하거나 말할 때 거의 사용하지 않습니다.
- 한자어나 번역어가 문장 관계를 숨깁니다.
- 일반적인 동사로 쓸 수 있는데 명사화한 표현을 사용합니다.

고유한 학술 개념, 법률 용어와 정확성이 필요한 기술 용어는 익숙하지 않다는 이유만으로 바꾸지 않습니다. 필요한 경우 첫 등장에 짧게 설명합니다.

## 5. 대표적인 번역투와 AI 관용구를 줄입니다

다음 표현은 문맥을 확인한 뒤 더 직접적인 문장으로 바꿉니다.

- `~에 대해 논의합니다` → `~를 논의합니다.`
- `~를 통해 개선합니다` → 수단이 중요하지 않으면 `~로 개선합니다.` 또는 실제 행동을 씁니다.
- `~에 있어서` → `~에서`, `~을 판단할 때`
- `~에 의해 생성됩니다` → 행위자를 주어로 씁니다.
- `~되어진다` → 단일 피동이나 능동으로 씁니다.
- `가지고 있다` → 구체적인 동사나 형용사로 씁니다.
- `~할 수 있다` → 가능성이 정보가 아니라면 현재 동작이나 조건을 직접 씁니다.
- `~라는 점`, `~다는 것이다` → 핵심 내용을 직접 서술합니다.
- `결론적으로`, `시사하는 바가 크다`, `주목할 만하다` → 삭제하거나 구체적인 결론을 씁니다.

표현 하나만으로 AI 문체라고 판정하지 않습니다. 반복, 문맥, 장르와 독자의 기대를 함께 봅니다.

## 6. 형식과 말투를 장르에 맞춥니다

- 요약, 브리핑, 체크리스트에는 불릿과 필요한 볼드를 사용합니다.
- 설명문과 보고서 본론에는 문단을 사용하되, 실제 병렬 항목은 목록으로 분리합니다.
- 원문이 해요체이면 해요체를 유지하고, 격식체이면 격식체를 유지합니다.
- 자연스럽게 보이려고 전문 문서를 임의로 구어체로 바꾸지 않습니다.
- 문장 길이와 종결어미를 억지로 다양하게 만들지 않습니다. 정보 구조에 따라 자연스럽게 달라지게 합니다.

## 7. 판단 순서

표현이 의심스러우면 다음 순서로 판단합니다.

1. 독자에게 필요한 정확한 용어입니까?
2. 해당 장르와 분야에서 실제로 통용됩니까?
3. 표현을 제거하거나 일반적인 말로 바꿔도 정보가 유지됩니까?
4. 대조, 비유와 강조가 실제 이해를 돕습니까?
5. 사용자가 요청한 어조와 형식을 유지합니까?

필요한 전문 용어와 실제 대조는 남깁니다. 의미를 보태지 않는 꾸밈과 기계적인 직역은 제거합니다.
